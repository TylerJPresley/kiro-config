# Features

Intent: work is organized into self-standing features, each carried by one plan with a clear outcome.
Applies: when scoping, planning, closing or releasing work.

- Larger work is organized into features. A feature is a complete unit of work carried by one plan, with a one-sentence outcome. It may change what a user sees or not.
- A feature stands on its own: when it closes, the system works without any later feature. It is planned and built that way.
- A feature is complete when its criteria pass and the blueprints, the code and the repo documents agree.
- A feature too big for one plan is split into smaller features.
- The plans, in order, are the roadmap. A plan starts as an outline with its one-sentence outcome and is expanded into a full plan when its turn comes. The owner sets the order through discovery.
- A closed feature leaves behind a feature tag, a changelog entry, its plan archived, a handoff that points to the next feature, and its push to origin. A real-environment check runs first when behavior a user sees changed.
- A dropped feature has its plan archived with the reason.
- A release leaves behind a release tag that the owner chooses and ships, after a real-environment check, a security audit and the changelog.
